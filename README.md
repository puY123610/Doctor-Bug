# Doctor Bug

多智能体编排、调度、执行与验证平台。2026 第五届“未来杯”赛题一参赛作品，队伍：快创 & 超新星，正式提交命名。

命令名与 npm 包名均为 `drbug`。

## 它是干什么的

Doctor Bug 是一个在你自己电脑上运行的程序。你把一个代码项目交给它，它会为这个项目组建一支 AI 小队，自动完成一整套工作：

1. **建档组队**：先把项目扫一遍、把项目自带的测试跑一遍，摸清哪里有毛病；再按项目结构组建小队——一名主治医生负责调度和汇报，几名修理工各管一块文件，每个人都有自己的身份档案和负责范围。
2. **先复现，再动手**：先把毛病稳定地重现出来，重现不了就不乱改。
3. **按证据派活**：哪个测试失败、失败信息指向哪块文件，就把活派给管那块的人。派活依据是真实的失败结果，不是让模型自由猜测。
4. **修完由事先定好的检查判卷**：修得对不对，不由 AI 自己说了算，而是跑项目自己的测试来判定。这套检查在开工前就单独存放、定死，干活的 AI 改不了它——改了立刻判定作弊、本轮作废。
5. **没过就改派**：判卷没过，带着新的失败结果换人或换修法再来一轮，直到全过或者轮数用完。
6. **出成绩单，老板拍板**：最后给出一份结果——一共查出几个毛病、修好几个、原来好的地方有没有被带坏。主治医生用大白话汇报，最终采纳不采纳由你决定。

## 解决什么问题

- **代码改一处、坏一片，人工排查慢**：项目一大，改动引起的连锁毛病靠人逐个找，费时又容易漏。Doctor Bug 先把全套测试跑一遍定位毛病，再按毛病的位置自动分工。
- **让 AI 自己修、自己说修好了，不可信**：模型给自己打分很容易放水。这里判卷的是事先定好的测试程序，不是模型；修没修好，有硬标准。
- **多个 AI 一起干活容易乱**：谁干什么、干完谁验、没过怎么办，都由平台的调度规矩管着——派活看证据、判卷走程序、每一步都有记录可查。

## 支持的语言

平台检查和修复的对象是项目代码，目前支持三种语言：

| 语言 | 支持情况 |
|---|---|
| Python | 支持。已在真实的第三方开源项目上端到端验证过：建档、复现、修复、判卷全程跑通。 |
| JavaScript / TypeScript | 支持。检查、派活、修复的机制齐备。 |
| Go | 支持。检查、派活、修复的机制齐备。 |

一条共同的边界：**只能修“测试能判出来”的毛病**。判卷靠的是项目自带的测试——项目没有测试覆盖到的地方，平台发现不了，也不会假装修好。

## 安装

### 方式一：环境打包版（推荐，macOS 苹果芯片）

包里自带 Python 运行时和全部依赖，装上就能用，不用自己准备环境。

```bash
git clone https://github.com/puY123610/Doctor-Bug.git
cd Doctor-Bug
bash npm/build_bundled.sh
npm install -g ./npm/dist-bundled/drbug-bundled-0.1.0-darwin-arm64.tgz
```

装完在任意项目目录里敲 `drbug` 即可打开。

说明：npm 官方仓库尚未正式发布，现阶段从本仓库构建安装。

### 方式二：源码版（macOS / Linux）

需要 Python 3.11 以上（本项目在 Python 3.12.16 上实测）。macOS 请用 Homebrew 的 Python，不要用系统自带的：

```bash
brew install python@3.12 # macOS；Linux 用发行版的 python3.12
git clone https://github.com/puY123610/Doctor-Bug.git
cd Doctor-Bug
/opt/homebrew/bin/python3.12 -m venv .venv # macOS（Homebrew）；Linux 改用 python3.12
.venv/bin/python -m pip install -r requirements.txt
./drbug
```

嫌一步步敲命令麻烦的，可以用仓库根目录的一键启动脚本：macOS 双击 `双击启动.command`，Linux 在终端里运行 `./start.sh`。第一次运行会自动建好环境、装好依赖，之后每次直接打开；运行前请先装好 Python 3.12（没装时脚本会停下来说明怎么装）。仓库里还有一个实验性的 `start.bat`，但产品本身在 Windows 上未适配、未验证，请勿在 Windows 上用于正经项目。

## 配置

第一次打开 `drbug` 会进入配置引导，一步步来：

1. **选一家模型供应商、填你的 API 密钥**。密钥只存在你本机的配置文件里，不上传到任何服务器（本产品没有服务器，全部在本机运行）。
2. **每次进入一个项目目录，都会先问你是否信任这个目录**，你同意了才开始工作；拒绝就退出。这个选择不保存，每次进入都重新问。
3. 之后就是自动建档组队，然后你可以让主治医生开始检查和修复。

模型方面：平台已接通 8 家供应商的调用（DeepSeek、Anthropic、阿里云百炼、MiniMax、Moonshot、OpenAI 两种接口、火山引擎），可以在界面里用 `/model` 切换供应商、模型和思考档位。其中**只有 DeepSeek 经过真实密钥端到端验证**，其余各家只完成了接线和离线验证，选它们时请先小范围试用。

配置文件示例见仓库里的 `model_config.example.json`。

## 使用前须知

- 员工（Agent）的记忆是真实存在的机制——每个人有自己的记忆文件、会积累经验；但记忆对修复效果的帮助，我们做过两次对照实验都没有测出明确差别，所以不宣称它有效。
- 平台修复的前提是项目自带可运行的测试；没有测试的项目，建议先补测试再交给它。
