# 仓库分诊流程（无测试仓库）

适用于「没有测试套件、只有症状描述」的仓库。次序不可颠倒：先复现，再定位，最后才谈冻结验收。

1. **确认症状可复现**：按报告者的步骤在本机跑一遍，记录实际输出与期望输出的差异。复现不了就先向报告者要确切的输入与环境，不许凭猜测动手。
2. **写最小复现**：把症状收敛成一个可重复执行的最小脚本或单测，放在仓库的 tests/ 下（命名 test_repro_<主题>.py）。复现必须在未修复代码上稳定失败。
3. **定位模块**：从复现的失败回溯找责任文件；跨模块时先用二分/日志缩小范围，不许全仓漫改。
4. **修复并回归**：修复后最小复现转绿，再跑仓库现有的全部检查（哪怕只有零散脚本），确认没有把别的行为改坏。
5. **冻结验收**：复现测试经老板确认后可冻结进验收金库，作为这个仓库的第一份冻结验收；冻结前不许改复现的断言来迁就实现。

注意事项：

- 复现脚本里不许写密钥、真实用户数据；用假数据。
- 症状描述与实际行为不一致时，以实际复现结果为准，并把差异记下来。
- 修不动时停下来报告卡点（复现、已排除的方向、还缺什么信息），不许静默扩大改动范围。
